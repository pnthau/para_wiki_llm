# Tổng hợp Kiến thức Spring MVC & Core - Section 02

## 1. Phân biệt Model, ModelMap và ModelAndView

| Tiêu chí | Model | ModelMap | ModelAndView |
| :--- | :--- | :--- | :--- |
| **Bản chất** | Là một **Interface** trong Spring UI. | Là một **Class** kế thừa từ `LinkedHashMap`. | Là một **Class** chứa cả **Model** (Dữ liệu) lẫn **View** (Giao diện). |
| **Cách dùng** | Được tiêm vào làm tham số của hàm. Trả về `String` (tên View). | Tương tự `Model`, nhưng có thể gọi chuỗi hàm `.addAttribute().addAttribute()`. | Khởi tạo đối tượng `new ModelAndView()`, đặt tên View và gán dữ liệu vào rồi `return`. |
| **Mức độ phổ biến** | 🔥 **Dùng nhiều nhất** (Code sạch, nhẹ nhàng). | ⚠️ Ít dùng hơn. | 🏛️ Thường gặp trong code Spring MVC cổ điển. |

### Ví dụ code:
- **Với `Model`**:
```java
@GetMapping("/users")
public String getUsers(Model model) {
    model.addAttribute("users", userService.findAll());
    return "user-list"; // Trả về tên file HTML/JSP
}
```

- **Với `ModelAndView`**:
```java
@GetMapping("/users")
public ModelAndView getUsers() {
    ModelAndView mav = new ModelAndView("user-list"); // Đặt tên View
    mav.addObject("users", userService.findAll());   // Đặt dữ liệu
    return mav;                                      // Trả về cả gói MAV
}
```

## 2. Ý nghĩa của @RequestMapping và các biến thể

- **Ý nghĩa cốt lõi**: `@RequestMapping` đóng vai trò là **tấm bản đồ chỉ đường (Routing Map)**, liên kết một HTTP Request từ phía Client (dựa trên URL, HTTP Method, Headers...) vào đúng Controller hoặc Handler Method trong Java để xử lý.
- **Các biến thể (Composed Annotations từ Spring 4.3+)**:

| Annotation con | Tương đương với `@RequestMapping` | Mục đích RESTful |
| :--- | :--- | :--- |
| **`@GetMapping`** | `method = RequestMethod.GET` | Lấy / Đọc dữ liệu |
| **`@PostMapping`** | `method = RequestMethod.POST` | Tạo mới dữ liệu |
| **`@PutMapping`** | `method = RequestMethod.PUT` | Cập nhật toàn bộ dữ liệu |
| **`@DeleteMapping`** | `method = RequestMethod.DELETE` | Xóa dữ liệu |
| **`@PatchMapping`** | `method = RequestMethod.PATCH` | Cập nhật một phần dữ liệu |

## 3. Phân biệt @RequestParam và @PathVariable

| Tiêu chí | @RequestParam | @PathVariable |
| :--- | :--- | :--- |
| **Vị trí lấy dữ liệu** | Lấy từ **Query String** đằng sau dấu `?` (hoặc Form data). | Lấy trực tiếp **lồng bên trong đường dẫn URI Pattern**. |
| **Cấu trúc URL** | Có cấu trúc `key=value` (VD: `/products?id=3&page=1`). | Không có `key`, chỉ có giá trị (VD: `/products/3`). |
| **Cú pháp Controller** | `public String get(@RequestParam int id)` | `@GetMapping("/{id}")` + `public String get(@PathVariable Long id)` |
| **Ngữ cảnh sử dụng** | Dùng cho **Lọc, Tìm kiếm, Phân trang, Sắp xếp** (`?sort=asc`). | Dùng để **Định danh chính xác 1 tài nguyên cụ thể** (Resource ID). |

## 4. Ý nghĩa của RedirectAttributes

- **Vấn đề giải quyết**: Khi áp dụng mô hình **PRG (Post-Redirect-Get)** để tránh lỗi lặp Form khi bấm F5, lệnh `redirect:/url` sẽ tạo ra một Request hoàn toàn mới, khiến toàn bộ dữ liệu lưu trong `Model` cũ bị **xóa sạch**.
- **Ý nghĩa của `RedirectAttributes`**: Giúp **chuyển tiếp và giữ lại dữ liệu** (như thông báo thành công `"Thêm mới thành công!"`) sang trang mới sau khi Redirect.
- **Cách hoạt động của `addFlashAttribute()`**:
  1. Tạm thời cất dữ liệu thông báo vào `HttpSession`.
  2. Sau khi trang mới (`GET`) hiển thị thông báo xong, Spring **tự động xóa ngay dữ liệu đó khỏi Session** (chỉ sống đúng 1 lượt chuyển tiếp ⚡ như một tia chớp - Flash).
